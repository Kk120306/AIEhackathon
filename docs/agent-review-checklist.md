## Important: Convex ID Typing

Convex returns document IDs as `Id<"sessions">` (a branded/nominal string subtype), not plain `string`. The contracts file uses `string` for portability, but:

- When passing `_id` / `sessionId` **into** Convex mutations or queries from `app/page.tsx`, cast explicitly:
  ```ts
  saveMessageMutation({ sessionId: sessionId as Id<"sessions">, ... })
  ```
- Do **not** spread raw Convex rows directly into components that expect the `Session` / `Message` / `Progress` contract shapes — TypeScript will complain. Use a thin mapper or `as unknown as Session`.

## Watch-for: `topic` Detection in `lib/askTutor.ts`

The dashboard plan (section 5.2) shows adding `topic?: string` to the Gemini response. The `askTutor` function currently returns only what Gemini's parts contain. For `topic` to be populated reliably:

1. The system prompt (`lib/prompts.ts`) must instruct Gemini to always include a `topic` field in its JSON/structured output, **or**
2. A post-processing step must be added in `lib/askTutor.ts` to extract the topic from the response text.

Without this change, `nextResponse.topic` will always be `undefined` and `saveMessage` / `addTopicToSession` mutations will do nothing useful.

## Watch-for: `is_correct` Signal Source

`is_correct` is listed as `boolean | undefined` in `TutorResponse`. Currently Gemini does not return this field. The integration agent needs to either:

- Extend the system prompt to explicitly ask Gemini to emit `"is_correct": true/false` when the student attempts an answer, **or**
- Implement a lightweight heuristic in `lib/askTutor.ts` (e.g. check if Gemini's text includes "correct", "well done", "that's right" etc.).

Until this is done, `upsertProgress` will never be called with meaningful data and the accuracy charts will show no data.

## Watch-for: `app/layout.tsx` Modification

The dashboard plan wraps the root layout with `<ConvexProvider>`. The current `layout.tsx` (line 26–35) is a pure server component — adding `ConvexReactClient` makes it a client component boundary. Ensure you add `"use client"` **only** to a wrapper component and keep the root layout as a server component, e.g.:

```tsx
// app/providers.tsx  (new file)
"use client";
import { ConvexProvider, ConvexReactClient } from "convex/react";
const convex = new ConvexReactClient(process.env.NEXT_PUBLIC_CONVEX_URL!);
export function Providers({ children }: { children: React.ReactNode }) {
  return <ConvexProvider client={convex}>{children}</ConvexProvider>;
}
```

Then import `<Providers>` inside `layout.tsx` without marking `layout.tsx` itself as a client component.

## Watch-for: `ConversationMessage` Role Union

`ConversationMessage.role` in `app/page.tsx` and `lib/askTutor.ts` includes `"system"` as a valid role. The Convex `messages` table (per the schema plan) only stores `"user" | "assistant"`. The integration agent must filter out system messages before calling `saveMessage`, which `lib/askTutor.ts` already does for Gemini history (line 36–41) — replicate that guard in `app/page.tsx`.
